# 0025 提案を追加したらその場で項目のシートを開き、最初の一歩と AI に聞くを項目に残す

- 日付: 2026-11-04
- 状態: 仮決め（スマホで触って確かめる）
- 対象: SPEC.md（版）、screens.md §3・§5・§8、api.md §2・§4、metrics.md §6、testing.md §5。0021 の「相談文は共通のまま」を、提案から追加した項目について見直す

## 決めたこと
- 提案 1 件の画面の [♡ やりたいリストに追加] を、画面の下（タブバーの上）に固定する。押したら、トーストではなく、その場で項目のシート（提案から開く形）を開く
- 提案から開くシートは、上に「やりたいリストに入れました」と [取り消す] を出す。🎉 と削除の行は出さない。予定日が未定なら「今は決めなくて大丈夫です」と添え、一番下に [ほかの提案を見る] を置く
- [取り消す] は確認なしで消す。達成記録があるときだけ確認する
- 追加済みのボタンは「✓ やりたいリストにあります」にし、押すとシートを開き直す（あとから取り消せるように）。やったリストにある提案は、やったリストと同じシートを開く
- 提案から追加した項目のシートには、どこから開いても、最初の一歩と [💬 AI に聞く] を出す。相談文は「まずは、最初の一歩を教えてください」に、提案の最初の一歩を手がかりとして添える。そのために `GET /api/options/:id` が `firstStep` を、`GET /api/suggestions/:id` が `optionId` を返す
- 項目のシートは、戻る（ブラウザ・Android のジェスチャー）でも閉じる。開いたら同じ URL の履歴を 1 つ積む。やりたいリスト・やったリストのシートにも効く
- 提案 1 件の画面で、見出しと豆知識を 1 枚の白いカードにまとめ、テーマの色の線・丸とテーマ名（押すとテーマの一覧へ）を付ける
- 利用イベントに `suggestion_undo` を足す。採用率から取り消しを引き、取り消し率を別に観測する

## 理由
- ユーザーから、提案 1 件の画面について次の声があった
  - 追加の導線が弱い
  - 追加すると最初の一歩が消え、追加したことも分かりにくい
  - 追加済みをすぐに戻せない
- 調べると、追加ボタンは豆知識・最初の一歩・タグの下にあった。豆知識が長いと画面の下に沈む。追加した option はタイトルと提案の ID しか持たず、やりたいリストのシートに最初の一歩が出ていなかった
- モックアップで 3 案を比べた
  - 案A: 押したらその場に小さなパネル
  - 案B: 押したら項目のシート
  - 案C: 最初の一歩を主役にし、追加を脇役にする
- ユーザーは A と B で迷い、混ぜる形を選んだ。条件は 3 つ
  - AI に聞くは入れる
  - カレンダーは出すが、すぐ決めなくてよいと添える
  - 🎉 は要らない（追加してすぐ終わることはまずない）
- 項目のシートには、もともと予定日と AI への相談がある。0014 で決めた「アプリの中では、いつやるかと、外で計画を始めるきっかけだけを持つ」に、そのままつながる。部品を新しく作らずに済む
- 相談文を共通のままにした 0021 は、何を聞くかが人によって違う、という理由だった。提案から追加した項目には、聞く入口（最初の一歩）がはっきりある。そこで、最初の一歩を手がかりに添える。文は今までどおりその場で直せる
- [取り消す] に確認を出すかを話した
  - 最初は、「直前の操作を戻す」と取り違えて、項目ごと消してしまうことを心配した
  - しかしユーザーの考えは「取り消すなら、予定日も含めて提案ごと取り消したい」だった。消しても追加し直せば戻る
  - そこで、追加し直しても戻らない達成記録があるときだけ確認する
- 戻るで閉じるのは、UX の見直しで出た懸念。提案の画面は履歴を積むので、シートを開いたまま戻ると前の提案へ移ってしまう。追加した直後に閉じようとして戻るを押すのは自然な操作
- 0017 で ✕ は置かないと決めている。ただ、追加したときのシートは自分で開いたものではなく勝手に出るので、閉じ方に迷いやすい。✕ の代わりに、次にやることを示す [ほかの提案を見る] を置く
- 追加のトーストは、シートの上の文と重なる。しかも固定ボタン・トースト・タブバーが下に 3 段重なるので、やめた
- 「やりたいリストにあります ›」の › は「別の画面へ移る」合図だが、実際に開くのはシートなので外した

## 影響
- backend: `OptionRepository.findDetail` が追加元の提案の `first_step` を LEFT JOIN で読む（SQL の本数は変わらない）。`SuggestionRepository.find` が option の id を読む
- frontend: `OptionSheet`（提案から開く形・最初の一歩・戻るで閉じる）、`ConsultButton`・`ConsultPrompt`（最初の一歩を聞く文）、`SuggestionDetailPage`（カード・固定ボタン・シート）、`useAddSuggestion`
- E2E: testing.md §5 の 4 番を、追加したあとのシート・取り消し・戻るで閉じる形に変える
