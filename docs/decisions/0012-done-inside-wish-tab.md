# 0012 やったリストをタブから外し、「やりたい」の中の切り替えにする（ステップ 4）

- 日付: 2026-11-01
- 状態: 確定
- 対象: screens.md §1・§2・§6、SPEC.md §3

## 決めたこと
- タブは「やりたい / 提案」の 2 つにする。やったリスト（`/done`）は、やりたいリストとやったリストのヘッダーの真ん中に、見出しの文字の代わりに置いた「やりたいこと｜やったこと」の切り替え（セグメント）で開く。`/done` を開いているときもタブは「やりたい」を選んだ表示にする
- 切り替えはヘッダーと一緒に下へのスクロールで引っ込み、少し上にスクロールすれば戻ってくる
- 切り替えはタップだけ（左右スワイプは入れない）。URL は `/` と `/done` のまま分け、切り替えは履歴に積まない
- 「準備中・検討中（やってる）」の状態は今は足さない。SPEC.md §3 の未決事項に残す

## 理由
- やったリストは振り返りのときに開くくらいで、毎日タブで行き来する画面ではない。同じ options の「状態ちがい」なので、別の画面よりも同じ画面の中の切り替えのほうが意味に合う（ユーザーの判断）
- スワイプは 0011 と同じ理由（提案画面のスワイプ、ステップ 9 のドラッグ、iPhone の端からの「戻る」とぶつかる）で入れない。スワイプだけだと切り替えられることにも気づきにくい
- 切り替えは、はじめ見出しの下に置いて一覧と一緒に流れる形にしたが、ユーザーから「スクロールした先からもすぐ切り替えたい」と声があり、ヘッダーに入れた。切り替えだけを別に固定する形は、ヘッダー（64px）・タブバー（約 78px）に加えて約 52px を常にふさぎ、一度に見えるカードが減る（0011 で「一度に多く見える」ことを優先した）ので採らなかった。見出しの文字と切り替えはほぼ同じことを言うので、選んでいる側を見出しの代わりにすれば、ヘッダーの高さを変えずに済む
- URL を分けたままにしたので、詳細画面から戻ったときや再読み込みでも、見ていた側（やりたい・やった）に戻る
- 「やってる」は、続けている趣味なら 🎉 の回数で表せる。準備中・検討中は別の状態だが、DB の `status`・API・マイグレーションまで変わる大きさで、このアプリの軸（ふと見て「やってみようかな」と探す）にどこまで要るかもまだ分からない。もとの想定は「やったことはないがやってみたい」ことなので、趣味になったものを同じ項目にメモで書き足すか、別のリストにするかと合わせて、使ってみてから決める

## 影響
- `features/options/StatusSwitch.tsx` を足し、`/` と `/done` のヘッダーで使う。`PageHeader` に、見出しの文字の代わりに真ん中に出すもの（`center`）を渡せるようにした。タブバーは選んでいる扱いにするルートをタブごとに持つ
- やったリストを開いているとき、「やりたい」タブには `aria-current="true"` を付ける（今のページを示す `page` は切り替えの「やったこと」だけにする）。それ以外の画面では、選んでいるタブに `page` を付ける
- 使わなくなったアイコン（check）を消した
- E2E: タブの行き来と、切り替えでやったリストを開くテストに分けた。ヘッダーの出し入れのテストは、見出しではなく切り替えが画面に見えるかで確かめる
