# 0023 探す画面を、今月のおすすめの大きなカードと横の棚に組み替える

- 日付: 2026-11-03
- 状態: 仮決め（スマホで数日触って、縦の一覧（案A）と比べ直す）
- 対象: screens.md §5・§8、性能用データ（backend/db/perf-data）の来た元

## 決めたこと
- 今月のおすすめを「11 月のおすすめ」として、画面の幅に近い大きなカードにする。濃いアクセント色の背景に、季節の終わりの月（「11 月まで」）・大きな見出し・タイトルと一歩の大きさ
- 一歩の大きさのチップを、ヘッダーの右の「絞り込み」ボタンにしまう。選んだまましまうと絞り込みも外す（しまったまま絞られていると、ほかの提案が消えた理由が分からなくなる）
- 「今日すぐできる」（1 時間以内で、通年か今月が季節のもの。テーマごと 1 件、最大 6 件）の棚を足す。チップを選んでいる間は出さない
- テーマ別の縦の一覧を、テーマごとの横の棚（最大 6 件。今月が季節のものを先に）にする。全件は「すべて N 件」からテーマの一覧（0022）で見る
- `suggestion_view` の来た元に `quick`（今日すぐできる）を足す

## 理由
- ユーザーの声は 3 つあった。1 つ目は、見出しは引きのある文なのに、画面全体がのっぺりしていて言葉が入ってこないこと。2 つ目は、一歩の大きさのチップが、目立つ場所に置くほど大事なのかということ。3 つ目は、今月のおすすめの横スワイプが目立たないこと
- モックアップで、今の形・案A（並びはそのままで強弱を付ける）・案B（この形）を比べた。ユーザーは「案Aのほうが見やすいかもしれないが、案Bのほうが綺麗。どちらかといえば案B」と答えた
- 探す画面の目的は、ふらっと開いて目に留まった 1 件を開いてもらうこと（0020）。そのため、全件を漏れなく見られることより、1 件ずつの見出しが目に入ることを優先した
- モーダルで出す形と、自動で回るカルーセルは採らなかった。開くたびに出るモーダルは閉じる操作が増えるだけになりやすい。自動で回る形は読んでいる途中で動いてしまい、広告のように読み飛ばされやすい
- 「1 時間以内」は、絞り込みとしてより、「今日すぐできる」という中身の入口にしたほうが引きになる
- モックではテーマごとにカードの色を変え、期限のバッジを琥珀色にしていた。しかしトークンの色数が目標値（12 色）の上限ちょうどなので、今ある色だけで組んだ。色を足すなら目標値を見直す
- 棚の横の位置まで覚えると仕組みが大きくなる。縦の位置だけ戻せば、元の場所の近くには戻れる

## 影響
- frontend: 探す画面と行の部品（棚・大きなカードの形を足す）。API・データは変えない
- 性能用データの来た元に `quick` を足す。来た元は `suggestion_view` の中での番号で回す（全イベントの通し番号のまま割ると、イベントの種類の数（4）と来た元の数（6）に公約数があり、`list`・`quick`・`tag` が 1 件も入らなかった）
- E2E: チップを押す前に「絞り込み」を開く。今月のおすすめの名前は「12 月のおすすめ」のように月が入る
