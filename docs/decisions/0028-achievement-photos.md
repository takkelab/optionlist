# 0028 写真は達成 1 回に 1 枚付け、やったリストをタイルの 2 列にする

- 日付: 2026-11-06
- 状態: 仮決め（タイルの形は、使ってみて調整する。🎉 のあとの聞き方は 0029 で置き換え）
- 対象: SPEC.md（F3、§3）、screens.md §3・§4・§6、api.md §1〜§5、data.md §2、testing.md §2・§5、process.md §4

## 決めたこと
- 写真は達成記録に付ける。達成 1 回に 1 枚（`achievements.photo_filename`）。複数枚と、全体を大きく見る表示は入れない
- 付けられるのは 2 か所: 🎉 の演出のあとの「写真を残しますか？」と、シートの「達成した日」の行（あとから付ける・付け替える・消す）
- 🎉 のあとは、演出 →「写真を残しますか？」→（やりたいリストの項目なら）「やったリストに移動しますか？」の順に別々に聞く。移動の確認は写真の保存が終わってから出す
- やったリストは正方形のタイルの 2 列にする。写真の枠は作らず、写真なしは大きなタイトル、写真ありは全面の写真に文字を重ねる。写真は「写真が付いた達成のうち、いちばん新しいもの」
- 送る前に frontend で長辺 1280px・JPEG 品質 0.8 に縮め、backend は形式を先頭のバイトで確かめる。API は `PUT`・`DELETE /api/achievements/:id/photo` と、配信の `GET /api/photos/<ファイル名>`

## 理由
- 項目に 1 枚だと、繰り返しやることで写真が上書きされ、いつの写真か分からなくなる。回ごとに残せば「同じことでも毎回ちがう体験」（労いの文）とも合う。複数枚はテーブルと画面が増える割に、1 枚で足りる
- 写真がその場で手元にあるとは限らないので、あとからも付けられるようにした
- 別々に聞く形は、1 つのダイアログにまとめる案（おすすめとして出した）と比べ、ユーザーがキャンバスで見て選んだ。まとめる案は移動の確認の中に別の話が入る
- 写真を撮らない体験は多く、ユーザーの見立てでも半分以上に写真が付かないかもしれない。そこで、写真がない項目を例外にしない形にした。同じ絵のデフォルト画像を置くと「足りないもの」に見え、「やらなくてもいい選択肢」という考え方に反する。テーマごとの絵は手動で追加した項目に使えず、自動の色や模様は意味がないうえ 0024 の「虹の色は縁だけ」に反する
- 1 列に戻す案も比べたが、画面に入る件数は 2 列のタイルとほぼ同じで、写真の楽しさが小さく、やりたいリストとも似てしまう
- canvas を通すと EXIF（撮った場所など）も消える。縮めるので 5MB の上限にもまず当たらない

## 影響
- 移動した日は右端からタイルの下に移した。達成回数と同じ行に出す
- 写真を変えたら `GET /api/options/:id` を読み直してカードの写真をそろえる（カードの写真は backend が決めるので、手元で計算しない）
- 写真のファイルの置き場所（`LocalPhotoFiles`）は repositories に置いた。services から読むインタフェースを持つので、層の向き（services → repositories → infra）に合わせた
- option の削除は、先に写真の名前を読んでから行を消す（CASCADE のあとでは読めない）ので SQL が 1 本増える。達成の写真のアップロードは SQL 3 本（metrics.md §4 の上限どおり）
- 性能用データの達成の 3 件に 1 件に写真の名前を入れた（一覧の相関サブクエリを測るため。ファイルは置かない）
- 一覧がタイルの写真を読むサブクエリが増えたので、`achievements` のインデックスを (option_id, achieved_at, photo_filename) に広げ、行を読みに行かずに答えられるようにした（metrics.md §4 の SQL の目標）
- 同じ達成への写真の操作が同時に走ると、古いファイルが残ることがある。単一ユーザーのアプリなので排他はせず、画面で保存中の操作を止めて入口を塞ぐ（2 台で同時に操作したときだけ起こりうる）
- ログインがないので、同じ Wi-Fi の人からも写真を見られ、変えられる。これまでのタイトルと違って個人の写真なので、信頼できる Wi-Fi でだけ `dev:lan` を使う運用にする（CLAUDE.md、SPEC.md §3）。backend を PC の中だけで待ち受けても、`dev:lan` は Vite 経由で `/api` を公開するので防げない。認証はスコープの外のまま
- 下側を暗くする影は新しい色を足さず、`--color-backdrop` を 2 枚重ねて作る（metrics.md §3 の色の数の上限）
