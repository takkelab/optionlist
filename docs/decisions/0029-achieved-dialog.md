# 0029 🎉 のあとの写真と移動の確認を 1 つのダイアログにまとめる

- 日付: 2026-11-07
- 状態: 仮決め（使ってみて調整する）
- 対象: SPEC.md（F4）、screens.md §4、testing.md §5。0028 の「別々に聞く」を置き換える

## 決めたこと
- やりたいリストの項目では、🎉 の演出のあとに「やったリストに移動しますか？」だけを聞き、その中に写真の枠（破線の枠に「写真を残す」「なくても大丈夫です」）を置く。押さなくても答えられる。形は 0028 のときにキャンバスで描いた案 B（PhotoFlowB1・B2）のとおり
- 選んだ写真はその場で保存し、保存の間は答えられない。[このまま残す] でも写真は残る
- やったリストの項目は移動の話がないので、今までどおり「写真を残しますか？」 [あとで] [写真を選ぶ] を出す

## 理由
- 写真はオプションで、付けない達成のほうが多いかもしれない（0028）。そのたびに [あとで] を押すのが手間だと、ユーザーが判断した
- 移動を聞くダイアログの中なら、写真を飛ばす操作がなくなる。0028 で気にした「移動の確認の中に別の話が入る」は、問いかけにせず控えめなボタンにして抑える
- 保存を待ってから答えるのは 0028 と同じで、移した先の一覧を読むときに写真を間に合わせるため

## 影響
- 移動に失敗したら確認に戻す。移す入口はこの確認だけで、🎉 を押し直すと達成が余分に増えるため
- `ConfirmDialog` に `children` と `busy` を足した。`busy` の間は Esc を無視する。ただし Chromium は操作なしで続けて押された Esc を止めさせないので、閉じることがある。そのときは「このまま残す」と同じ結果で、保存は続くので、これ以上は止めない
- `ConfirmDialog` の最初のフォーカスを、やめるほうのボタンに固定した（今までもそこに当たっていた。中に足したボタンへ移らないように）
- シートの戻るは保存中でも効く。シートと確認は閉じ、保存は続く（0028 と同じ）
