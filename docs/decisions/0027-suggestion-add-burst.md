# 0027 追加ボタンを白地の枠にし、押したら塗られて ♡ が弾み、虹の粒がはじける

- 日付: 2026-11-05
- 状態: 仮決め（ティールの色そのものは、最後のほうで見直す）
- 対象: screens.md §1・§5、testing.md、SPEC.md（版）

## 決めたこと
- 提案 1 件の画面の [♡ やりたいリストに追加] は、押す前を白地にティールの枠と文字（♡ は線だけ）にする。追加した後（追加済み・やった）はティールで塗り、♡ も白く塗る。文字は「やりたいリストにあります」「やったリストにあります」（✓ をやめ、塗った ♡ で示す）
- 押したら、応答を待たずにボタンを塗り、♡ が弾み（縮んでから 1.3 倍まで大きくなり、元に戻る）、♡ から輪が広がって消え、まわりにアイコンの虹の輪の 10 色の粒がはじける（0.7 秒）
- 項目のシートは、押してから 0.4 秒たってから開く（応答がそれより遅ければ応答のあとで）。追加できなかったら、塗りを戻してエラーのトーストを出す
- 視差効果を減らす設定では、弾み・輪・粒を出さず、追加できたらすぐシートを開く
- 虹の色を縁以外に使うのは、この粒だけの例外にする（0024 は「縁にだけ使う」）。metrics.md §3 の検査でも、`AddButton.module.css` の `background` だけを許す。粒を box-shadow で描けば検査は通るが、決まりをすり抜けるだけなので採らない

## 理由
- ユーザーの要望。0026 で「押している間に色が濃くなる」形にしたが、ユーザーが思い描いていたのは X のいいねのような、押せたことがはっきり分かるエフェクトだった
- X のいいねが分かりやすいのは、押す前が色なし・押した後が色ありで、その切り替わりを弾みで見せるから。今までのボタンは押す前が濃い塗り・押した後が薄い色で逆だったので、エフェクトだけ足しても「色が付く」変化が使えない。そこで押す前を白地に枠、押した後を塗りに入れ替えた
- キャンバスに 3 案（A: 白地に枠 → 塗る / B: 白地のまま ♡ だけ色が付く / C: 今の塗りのまま ♡ が弾む）を置き、シートが開くまでの待ち（0〜1.2 秒）と粒の色を変えて触れるようにして、ユーザーが案A・0.4 秒を選んだ。待ちが短いとボタン（画面の下）がシートに隠れてエフェクトが見えず、長いとシートが開くまでもたつく
- 応答を待たずに塗るのは、押してから変わるまでの間をなくすため（X も同じ）。追加の API は速く、失敗はまれなので、失敗したときだけ戻す
- 粒の虹の色は、アプリのアイコンの虹の輪から取った色で、このアプリらしさが出る。0.7 秒で消える一瞬の飾りなので、0024 が防ぎたかった「画面が色でうるさくなる」ことにはならない
- ティールの色そのもの（濃い緑に見える）は、ユーザーが最後のほうでまとめて見直したいとのことなので、ここでは変えない

## 影響
- ボタンを `AddButton`（features/suggestions）に切り出した。弾みと、シートを開くまでの待ちは `useAddCelebration` が持ち、`useSuggestionSheet` の追加が待ちが終わるのを待ってからシートを開く。待っている間に止めたとき・画面を離れたときは、待ちを解いて先へ進める（押せないままにならないように）
- 409 のあとの開き直しを `useReloadAndReopen` に分けた（関数の長さの決まりに収めるため）
- ボタンの文字から ♡・✓ の記号をなくし、♡ は SVG で描く（読み上げはボタンの文字だけ）
- 0026 で足した `--color-accent-soft-pressed` は使わなくなったので消した
- E2E: 押すと塗られて弾み・粒が動き、それからシートが開くこと、視差効果を減らす設定では動かさないこと（suggestion-motion.spec.ts）。ボタンの文字の期待値を直した
