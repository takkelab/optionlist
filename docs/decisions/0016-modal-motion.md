# 0016 モーダルの出方と消え方（ステップ 5 の UX 改善）

- 日付: 2026-11-03
- 状態: 確定（速さは仮決め。触って調整する）
- 対象: SPEC.md（版）、screens.md §1・§3

## 決めたこと
- 下から出るシートは、下から滑り上がって出て（0.28 秒）、閉じるときは下へ滑って消える（0.2 秒）
- 持ち手を引いて離したときは、閉じるなら離した位置から下へ滑り、閉じないなら元の位置へ滑って戻る。80px より下で離すか、素早く下へ払ったら閉じる
- 中央のダイアログ（追加・削除の確認・AI に相談）は 3 つとも同じ動きにそろえる。少し小さく透明な状態から出て（0.18 秒）、薄くなって消える（0.12 秒）
- OS の「視差効果を減らす」が有効なら動きを付けない
- モーダルの動きは CSS で作る（Motion は使わない）

## 理由
- 出てきた方向へ戻すのは iOS・Android（Material Design）の基本で、どこから来てどこへ行ったかが分かる。下から来たシートがその場でパッと消えるとつながりが切れる（ユーザーと相談して決めた）
- 閉じるときを出るときより速くするのは、閉じたい人をシートの動きで待たせないため
- 持ち手を離したときに、その位置からパッと消える・パッと戻るのも同じくつながりが切れるので、離した位置から続けて動かす。払う操作で閉じるのは iOS のシートと同じ
- 中央のダイアログは、AI に相談だけを動かす案もあったが、同じ見た目のダイアログで出方が違うとちぐはぐに見えるので、3 つともそろえた（ユーザーの判断）。0.2 秒以下の短い動きなら待たされる感じはない。AI に相談では「押したらシートの上に何かが重なった」と目で追える助けにもなる
- モーダルは `<dialog>` の開け閉めに合わせて動かすだけなので、CSS のアニメーションで足りる。閉じる動きが終わってから `close()` する（動きの終わりは `getAnimations()` で待つ。視差効果を減らすときは動きがないのですぐ閉じる）。Motion（architecture.md §1）は、カードの入れ替わり・スワイプ・🎉 のような、並びや指の動きに合わせるものに使う

## 影響
- 閉じる動きの間も中身を出しておくため、開いている項目や相談文が null になっても、直前の中身を残して描く
- 閉じてから消えるまで 0.12〜0.2 秒かかる。E2E は消えるのを待ってから次に進む。タップ領域の計測は動きが終わってから測る
