# 0018 完了フローの演出、達成した日の見せ方、一覧から抜けるカードの消え方（ステップ 6）

- 日付: 2026-11-03
- 状態: 確定（労いメッセージの文言と動きの速さは使ってみて調整する）
- 対象: screens.md §1・§3・§4・§6、SPEC.md §3

## 決めたこと
- 労いの演出: 画面の中央に 🎉 と労いメッセージのカードが弾むように出て、周りに紙吹雪（16 粒）が散る。1.5 秒で消え、押すと早送り。そのあと `pending` なら移動の確認を出す。視差効果を減らす設定では紙吹雪を出さず、カードも動かさない
- 労いメッセージ: ランダムに選ぶのをやめ、押す前の達成回数で 2 種類を出し分ける。初めては「新しい体験が／ひとつ増えたね」、2 回目以降は「同じことでも／毎回ちがう体験だね」（「／」は改行）。改行は文言に書き、1 行は 12 文字までにする
- 達成記録の見せ方: 達成回数（🎉×3）に加えて、シートに「達成した日」を新しい順に並べる。シートを開いたときと 🎉 のあとに詳細 API を読む
- 一覧から抜けるカード（移す・戻す・削除）: シートが閉じるのを待って、高さが縮みながら薄くなって消える。トーストで知らせ、「元に戻す」は付けない
- [やりたいリストに戻す] は確認なしですぐ戻す

## 理由
- 演出・見せ方・消え方の 3 点はユーザーに選んでもらった（演出は「中央にカード＋紙吹雪」、見せ方は「回数＋日付の一覧」、消え方は「縮んで消える＋トースト」）
- 演出はこのアプリの軸（新しい体験への一歩を後押しする）なので、ボタンが弾むだけより目に留まる形にした。全画面の演出は毎回だと重いので採らなかった。紙吹雪の位置は乱数を使わず放射状に均等に置く（テストで確かめられ、1 秒ほどの動きなので毎回同じ形でも気にならない）
- 演出をシート（モーダルの dialog）より上に出すため、トーストと同じく popover にした。画面全体を覆うので、演出の間に下のシートを押し間違えない
- 労いメッセージは、アプリのコンセプト（やってもいいし、やらなくてもいい選択肢。新しい体験への一歩の後押し）に合わせて、ユーザーと相談して決めた
  - 「えらい」のような評価の言葉は、ほめられるためにやる方向へ寄りやすいので使わない。「いい経験になったね」のように気持ちを決めつける言葉は、うまくいかなかった日にずれる。「次は何をやってみる？」は、やり終えた瞬間に次の課題を渡し、義務感に戻すので使わない
  - 初めての 🎉 は「新しい体験への一歩」、2 回目以降は「同じことでも毎回が新しい体験」と、どちらもアプリの軸を同じ言葉で伝える。ランダムな 8 種類より意味がはっきりし、毎回同じ言葉が「やった」の合図になる。繰り返す項目（ボルダリングの 10 回目など）で「新しい景色が増えたね」のようなずれも起きない
  - 2 回目以降を問いかけ（「前と違う発見、あった？」）にする案もあったが、1.5 秒で消えて移動の確認に切り替わるので考える時間がなく、何もなかった日には宿題のように感じるので、受け止める言葉にした
  - 文言は 12 文字を超えるとブラウザが言葉の途中で折り返す（文節で折り返す CSS の `word-break: auto-phrase` は iPhone の Safari が対応していない）ので、改行を文言に書く。UT で 1 行の長さを確かめる
- 消え方は、削除と移動が同じ見た目（シートが下へ消えるだけ）で分かりにくいという 0017 の声に合わせ、カードの動きで「リストから抜けた」ことを見せる。「元に戻す」は、削除を戻すと予定日・達成記録まで戻す仕組みが要るので入れない。移した・戻したものは反対側のリストから戻せる
- 戻すのは取り消せる操作（もう一度 🎉 から移せる）なので確認を挟まない

## 影響
- backend: `POST /api/options/:id/achievements` を `AchievementsController`・`AchievementService`・`AchievementRepository` で足した（書いた値を読み直さず返し、SQL は 1 本）
- frontend: `motion` を入れた（`LazyMotion` ＋ `domAnimation`。初期表示の JS は 109KB → 139KB、上限 200KB）。`CollapsingList`（components）、`completion/`（演出・🎉・移動の確認）、`AchievementHistory`、やったリストを足した。`OptionListActions` は並べ方（`ListOrder`）を受け取り、やったリストは移した日の順に並べる
- `ConfirmDialog` にやめるほうのボタンの文言（「このまま残す」）を渡せるようにした
- E2E: 削除のあとの並びは、カードが縮んで消えるのを待って確かめる（`WishListScreen.titleCells()`）
