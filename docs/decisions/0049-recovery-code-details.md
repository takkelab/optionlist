# 0049 復旧コードとすべてのデータを消すの細部（R3）

- 日付: 2026-11-09
- 状態: 確定
- 対象: data.md §4（`auth_restore`）、screens.md §9、process.md §5（R3・R6）、testing.md §1・§7

## 決めたこと
- `auth_restore` は、429 で断った試行を auth_attempts に入れない。数えるのは、合った・合わない・確認が要る（`needs_confirm`）の 3 つ。上限（1 つの IP から 1 時間に 10 回）は変えない。data.md §4 の「どの結果でも 1 行入れる」を直した
- 設定のシートの「データについて」の [プライバシーポリシー] [利用規約] のリンクは、ページを作る R6 で足す。R3 は「5 年間使わないと、データは消えます」の 1 行だけにした（ユーザーの判断）
- 設定のシートと 2 つのダイアログ・勧めるカードは、キャンバスで案を比べずに、screens.md §9 の文のとおり、今のシート（`Sheet.module.css`）とダイアログ（`Dialog.module.css`）の見た目で作った（ユーザーの判断）。色は増やしていない
- 自分のコードを自分の端末で入れたか（トーストを「引き継ぎました」だけにするか）は、画面が、引き継ぐ前と後のアカウントの `createdAt` が同じかで見分ける（API の応答の形は変えない）
- マイグレーションのテストのスナップショット（`SchemaSnapshot`）に関数（名前・引数・戻り値・持ち主・SECURITY DEFINER）を足した
- 引き継いだあとに今の端末の古いアカウントを消せなくても、新しい鍵の Cookie を返して成功にし、失敗はログに出す（api.md §6）
- 勧めるカードは、アカウントがない端末では出さない。設定のシートでコードを発行したときも、[控える] と同じく二度と出さない（screens.md §9）
- 形が違うコード（400。使えない 0・O・1・I・L を打ったなど）は、画面では合わないコード（404）と同じ「コードが違います」にする

## 理由
- 断った試行: 0048 の `auth_create_user` と同じ。数えると、`Retry-After` のとおりに待って試し直しても窓が延びて、また断られる。総当たりへの備えは「合わない試行も数える」ことで足りていて、1 時間に 10 回より速くは試せない
- リンク: `/privacy`・`/terms` のページは R6 で作る。先にリンクだけ置くと、R6 までは押すと何もない画面になる
- スナップショット: `auth_restore` のマイグレーションは関数だけを足すので、表・列・索引だけを比べると「up で何も変わらない」になり、1 本ずつ up / down するテストが落ちる（足し忘れた down も見つけられない）

- 古いアカウントの削除: `auth_restore` は自分のトランザクションで確定する（移った先の鍵の置き換えとコードの消費）。そのあとの削除で失敗を返すと、新しい鍵の Cookie が返らず、移った先のアカウントは前の端末の Cookie もコードも使えないまま、どこからも開けなくなる。残った古いアカウントは鍵を持つ端末がないので誰にも見えず、削除のジョブ（data.md §5）が保存期間で消す
- 勧めるカード: 「写真を保存した」は端末に覚えるので、すべて消したあとや前の端末で引き継がれたあとも残る。アカウントを見ないと、空の一覧の上にカードが出て、[控える] が 404 になる。設定のシートで発行したあとも出したままだと、[控える] で作り直しになり、控えたばかりのコードが使えなくなる（reviewer の指摘）
- 400 を「コードが違います」に: 入力欄は英数字なら何でも受けるので、O を 0 と打ち違えるとサーバーは形の違いとして 400 を返す。利用者から見れば合わないコードと同じで、トーストと `client_error` にする理由がない
