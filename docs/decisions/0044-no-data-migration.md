# 0044 今の個人の MySQL のデータは本番に移さず、本番は空から始める

- 日付: 2026-11-08
- 状態: 確定
- 対象: data.md §1、process.md §5

## 決めたこと
- 手元の MySQL（`optionlist`）にある自分のやりたいこと・達成・写真は、本番に移さない
- R1 の前に、MySQL のダンプ（`mysqldump --single-transaction optionlist`）と `backend/uploads/` を、リポジトリの外（手元の保存用フォルダ）に残す。リポジトリには入れない

## 理由
- ユーザーの判断。移すには、一度きりの移行スクリプト（MySQL を読んで Postgres に新しいアカウントとして入れ、写真を入れ物に上げ、復旧コードを出す）と、そのテストが要る
- 移さないので、MySQL の 13 本のマイグレーションの歴史を引き継ぐ必要がなく、Postgres の基準のマイグレーション 1 本にまとめ直せる（0034）

## 影響
- これまでの達成の記録は、本番では見られない
- 提案のマスターデータは今の内容（MySQL のマイグレーションを全部流した後の状態）を、そのまま基準のマイグレーションに写す。提案の ID は変えない（0021）
