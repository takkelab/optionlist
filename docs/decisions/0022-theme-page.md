# 0022 テーマの全件を縦に並べるテーマの一覧を足し、一覧の行の見出しを大きくする

- 日付: 2026-11-03
- 状態: 確定（探す画面の組み替えは別に決める）
- 対象: screens.md §1・§5・§8、testing.md §5

## 決めたこと
- テーマの一覧（`/suggestions/themes/:themeId`）を足す。見出しはテーマ名、上に件数、そのテーマの提案を id 順にすべて縦に並べる。一歩の大きさのチップでは絞らない
- 探す画面のテーマ名の右に「すべて 11 件」のリンクを置き、テーマの一覧へ移る
- 一覧の行の見出しを本文より一回り大きい太字にし、行間を広げる（探す画面・タグの一覧・テーマの一覧・関連のすべて）
- テーマの一覧から提案 1 件を開いたときの `suggestion_view` の来た元は `list`（テーマ別の一覧と同じ）に数える

## 理由
- ユーザーから「見出しは引きのある文なのに、画面全体がのっぺりしていて言葉が入ってこない」「一歩の大きさのチップは、目立つ場所に置くほど大事なのか」「今月のおすすめの横スワイプは目立たない」と声があり、モックアップで今の形・案A（並びはそのままで強弱を付ける）・案B（今月のおすすめを主役にし、テーマを横の棚にする）を見比べた。ユーザーは案B寄り
- 案Bにすると、棚の後ろのほうの提案が見られにくくなる。逃げ道として、テーマの全件を縦に見られる画面が要る。縦の一覧は、案Aで見やすかった形にする
- 見出しを大きくするのは案A・案Bのどちらでも効き、どちらを選んでも残るので、先に入れる
- 来た元を `list` にまとめるのは、どちらも「テーマで眺めて選んだ」ことに変わりがないため。分けて見たくなったら値を足す

## 影響
- frontend: ルートとテーマの一覧の画面を足す。`SuggestionBrowse` にテーマで引く処理を足す。API・データは変えない（一覧の API がテーマと提案を全部返している）
- 探す画面を棚に組み替えるか（案B）は、別に決めて SPEC を直す
