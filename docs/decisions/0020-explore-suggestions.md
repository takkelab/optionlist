# 0020 提案はスワイプで判定せず、眺めて関連へ移りながら探す

- 日付: 2026-11-03
- 状態: 確定（件数・タグの粒度は使ってみて見直す）
- 対象: SPEC.md（版・F8・§3）、screens.md §1・§5・§8、data.md §2、api.md §2・§4、metrics.md §6、testing.md §1・§2・§5、process.md §4、architecture.md §1・§3

## 決めたこと
- 提案画面のカードのスワイプ（右で追加・左でスキップ）をやめる。代わりに「今月のおすすめ（季節）」「一歩の大きさのチップ」「テーマ別の一覧」で眺め、提案 1 件の画面からタグや関連をたどって次の提案へ移る形にする。1 件・タグの画面は URL を持ち、履歴に積む
- 提案 1 件を「見出し（引き）」「豆知識」「最初の一歩」「やりたいリストに入れるときのタイトル」で書く。場所は特定せず、探し方を最初の一歩にする
- 中身は AI（開発中の Claude）が下書きし、ユーザーが直す。先に 10 件ほどの見本で書き方を合わせてから全件書く
- 追加済みの提案も隠さず、印を付けて出す
- 利用イベントの `suggestion_skip` をやめて `suggestion_view`（どこから来たかを付ける）にし、採用率の分母を「1 件の画面を開いた数」に変える
- ステップ 7 を 7a（データと API）と 7b（画面）に分ける

## 理由
- ステップ 7 の計画中に、ユーザーから「やってみたいを探すきっかけとして、この UI が合っているか見直したい」と声があり、壁打ちした。ユーザーから出た案は「一覧で眺めたい」「カテゴリ分けや、関連するものへどんどん飛びたい」「『一番星が綺麗な場所』のような、興味を引く書き方」
- いまの 100 件（学習 20・趣味・創作 30・体験・外出 25・小さな挑戦 25）は「近所の知らないカフェに入ってみる」のような、誰にでも当てはまる行動の指示が中心。これを 1 枚ずつ判定しても流し見で終わりやすい。効くのは UI より中身の書き方だと考え、見出し・豆知識・最初の一歩で書き直す
- 季節（期限があると一歩目を踏み出しやすい）と一歩の大きさ（大きな夢を小さな一歩にする）は、壁打ちで出した案からユーザーが選んだ
- 連想でたどるには、1 件ずつ URL を持つ画面のほうが、戻る操作でたどってきた道を戻れて自然（シートの中で中身を入れ替える形より）
- 追加済みを隠すと、関連のつながりが途中で切れる
- 場所を特定しないのはユーザーの選択。地域に寄せると中身が住む場所に縛られ、全国区の名所だと旅行の提案ばかりになる
- 「今日はこれどう？」（screens.md §2）がすでにランダムの役目を持つので、ランダムに出す入口は残さない
- アプリに提案の自動生成は入れない（SPEC.md §2.2 は変えない）。AI が書くのは開発中のマスターデータの下書き

## 影響
- データ: themes・tags・suggestion_tags を足し、suggestions を作り直す（category をやめ、hook・trivia・first_step・size・season_from・season_to・theme_id を持つ）。入れ替えのマイグレーションで、旧提案に付いていた options の suggestion_id は NULL にする
- API: `GET /api/suggestions/random` をやめ、`GET /api/suggestions`（全件の要約）と `GET /api/suggestions/:id`（1 件と関連）にする。追加は今の `POST /api/options { title, suggestionId }` のまま
- 一覧の API はマスターデータの表を全部読むので、metrics.md §4 のフルテーブルスキャンに当たる見込み。扱いは 7a で実際の EXPLAIN を見て決める（SPEC.md §3）
- Motion はカードのスワイプには使わなくなる（ほかの動きでは使い続ける）
